# 行政与宣传校招方法论

## 使用原则

本文件仅作为行政综合与宣传岗位面试出题、追问和答题的兜底框架，不覆盖用户提供的组织制度、活动、稿件、媒体、预算、数据、个人权限和项目事实。用户事实与 JD 优先；信息缺失时使用 `【待补充】`，不得把通用流程、虚构传播效果或组织成果包装成用户经历。

行政与宣传职责可能分离：行政侧重组织运转、事务保障、材料会务、资源和流程；宣传侧重信息采编、内容表达、渠道发布、舆情与形象。复合岗位应分别说明任务目标和结果，不用曝光指标替代行政保障价值。

## 核心目标

行政与宣传工作的核心是保障组织规范、高效、稳定运转，并以准确、适当、一致的内容连接内部成员和外部公众，维护组织形象、信息秩序与公共信任。

- 准确理解任务、对象、时限、标准和审批边界。
- 把会议、材料、活动、资产和协同事项组织到位。
- 将组织信息转化为准确、清晰、适配渠道的表达。
- 保障信息发布及时、一致、可追溯。
- 兼顾服务体验、资源效率、安全保密和舆情风险。

## 业务链路

行政事务链路：

```text
需求受理 → 目标与权限确认 → 事项拆解 → 资源与排期 → 审批协调 → 执行保障 → 异常处理 → 验收归档 → 反馈复盘
```

宣传事务链路：

```text
传播目标 → 受众与场景 → 信息采集核验 → 选题与内容制作 → 审核校对 → 渠道发布 → 互动与舆情监测 → 效果评估 → 资料沉淀
```

常见任务包括公文材料、会议活动、接待、档案、资产、文化建设、新闻稿、新媒体、内部宣传和舆情协助；出题应按 JD 选择，不默认岗位同时负责全部事项。

## 能力模型

| 能力 | 校招考察重点 |
|---|---|
| 任务理解 | 能否确认目标、对象、标准、时限和优先级 |
| 文字表达 | 能否做到事实准确、结构清楚、语体适配 |
| 统筹执行 | 能否拆解流程、资源、依赖、责任人与检查点 |
| 沟通协调 | 能否在多方诉求中明确边界并推动事项闭环 |
| 细节与规范 | 能否做好校对、版本、审批、留痕和归档 |
| 服务意识 | 能否理解内部成员、来访者或公众的实际需要 |
| 内容与渠道 | 能否根据受众和目标选择表达形式与发布渠道 |
| 风险意识 | 能否识别保密、安全、舆情、版权和现场风险 |

## 指标

- 行政效率：事项按时完成率、响应时长、会议准时率、审批周期、问题关闭率。
- 保障质量：差错率、返工率、设备或物资可用率、现场事故数、满意度。
- 资源管理：预算执行偏差、采购与使用合规率、资产盘点准确率、空间或物资利用率。
- 材料档案：按时交付率、校对差错率、版本可追溯率、归档完整率。
- 内容传播：目标受众触达、阅读/播放完成、互动、转载、活动报名或认知反馈。
- 舆情与响应：监测及时性、事实核验时长、响应闭环率、错误信息更正情况。
- 护栏指标：泄密、错发、侵权、负面舆情、投诉、现场安全和超预算。

宣传指标需与目标匹配，不以阅读量单独证明传播有效；行政工作也不能只追求速度而牺牲准确、合规和安全。

## 项目深挖

```text
任务背景 → 服务/传播目标 → 对象与约束 → 方案和流程 → 我的职责 → 协调与执行 → 异常处理 → 质量/效果证据 → 归档复盘
```

重点追问：

- 任务成功标准是什么，是保障、告知、动员、形象还是行为转化。
- 信息来源如何核验，版本、审批和发布权限如何管理。
- 用户本人负责材料、会务、内容、渠道、供应商还是统筹，哪些结果属于团队。
- 多任务并行时如何判断紧急性、重要性和依赖关系。
- 现场、发布或协同出现变化时，如何止损、升级和同步。
- 阅读、到场或满意度变化能否归因于具体动作。

## 场景题

- 两项重要活动时间冲突且资源不足：核实不可变约束，按影响和紧急程度排序，协调替代资源并及时升级。
- 稿件临发布前发现关键数据无来源：暂停发布，回溯权威来源和审批人，完成核验后再更新版本。
- 会议现场设备突发故障：启动备用设备或替代流程，优先保障核心议程，并记录问题复盘。
- 宣传内容阅读量低：先检查目标受众、选题、标题、渠道、发布时间和承接，不直接追求夸张表达。
- 网络出现涉及组织的负面信息：先监测留存和核实事实，按授权上报，不以个人账号争辩或擅自发布结论。

## 答案框架

行政或宣传项目题：

```text
任务目标与对象 → 约束和标准 → 我的职责 → 流程/内容方案 → 资源与协同 → 执行及异常 → 质量或效果 → 风险控制 → 归档复盘
```

行政或宣传场景题：

```text
确认事实、权限和时限 → 判断影响与优先级 → 形成主方案和预案 → 明确责任与沟通节奏 → 执行检查 → 异常升级 → 留痕复盘
```

没有真实发布数据、预算或个人权限时，可说明将如何验证和推进，不得回答成已经取得传播或组织成果。

## 正反例

正例：

> 我负责活动流程表和现场协调，不负责最终审批。我先按关键议程倒排场地、设备、嘉宾和物料节点，设置发布前校对与现场检查清单；临时有嘉宾改期时，我先确认核心议程影响，再同步主持、会务和宣传人员更新统一版本。

反例：

> 我组织能力和文笔都很好，独立办了一场大型活动，宣传阅读量很高，领导非常满意。

反例的问题：缺少目标、规模口径、个人边界、具体动作、审批与协同过程，也没有说明阅读量是否对应实际传播目标。

## 风险边界

- 不虚构活动规模、传播数据、领导评价、媒体关系、预算或个人审批权限。
- 不把团队、供应商、媒体或组织品牌带来的成果全部归为个人。
- 不发布未经核验、未经授权或超出公开范围的信息。
- 不泄露内部材料、人员信息、会议内容、档案和敏感行程。
- 不为追求流量使用夸张、误导、侵权、冒犯或不当剪辑内容。
- 不忽视公文规范、版权肖像、采购报销、档案、消防和现场安全要求。
- AI 辅助写稿、制图、摘要或舆情分析时需核验事实、来源、版权和敏感信息，并由责任人审核。
- 本方法论仅用于兜底结构，不覆盖用户事实、组织制度、宣传口径、审批权限和法律法规。
