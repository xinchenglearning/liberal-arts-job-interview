# 策划校招方法论

## 使用原则

本文件覆盖活动、内容、游戏、品牌或项目策划的通用能力，仅作面试出题与答题兜底，不覆盖用户给出的具体策划方向、作品设定、业务目标、个人贡献和项目数据。用户事实优先；无法确认的信息标记 `【待补充】`，不得把框架生成的创意写成既有经历。

## 核心目标

策划的核心是把目标、受众和约束转化为可执行、可体验、可验证的方案，而不是只提出创意。

- 理解项目目标和受众需求。
- 形成清晰主题、机制或内容主线。
- 把创意拆为流程、规则、资源和交付物。
- 预判用户体验、执行风险与异常情况。
- 根据反馈和数据迭代，沉淀可复用方案。

## 业务链路

```text
目标与背景 → 受众/用户洞察 → 核心命题 → 创意发散 → 方案筛选 → 机制与流程 → 资源排期 → 执行上线 → 体验与数据验证 → 复盘迭代
```

不同方向应替换链路重点：

- 游戏策划：核心体验、系统机制、数值/关卡、内容生产、测试迭代。
- 活动策划：参与动机、流程节奏、传播、现场/线上执行、转化承接。
- 内容策划：选题、人群、叙事、分发、反馈和栏目化。
- 品牌策划：定位、主题、创意表达、触点一致性和品牌资产。

## 能力模型

| 能力 | 校招考察重点 |
|---|---|
| 目标理解 | 能否区分创意目标、用户目标和业务目标 |
| 用户洞察 | 能否识别受众动机、障碍和场景 |
| 创意能力 | 能否提出与目标相关而非只求新奇的概念 |
| 机制设计 | 能否把概念转化为规则、流程和反馈 |
| 结构表达 | 能否让不同协作方准确理解并执行方案 |
| 项目管理 | 能否拆资源、排期、依赖与应急预案 |
| 数据与测试 | 能否用原型、试玩、反馈或指标验证 |
| 迭代复盘 | 能否接受约束并基于证据修改方案 |

## 指标

- 参与/触达：目标人群覆盖、参与率、到场率、内容打开或试玩人数。
- 体验：完成率、停留时长、关键步骤流失、满意度、推荐意愿。
- 内容：点击、完播、互动、分享、收藏、持续消费。
- 游戏：新手完成率、关卡通过率、留存、参与深度、平衡性反馈。
- 业务：线索、转化、复购、成本效率或品牌认知变化。
- 执行：准时交付率、预算偏差、事故数、返工率。
- 护栏：投诉、误导、负面舆情、作弊、内容安全和体验疲劳。

指标必须服务目标；艺术性或体验型项目可结合定性证据，不强行只用商业转化衡量。

## 项目深挖

```text
命题与目标 → 受众洞察 → 核心创意 → 备选与取舍 → 机制/流程 → 个人产出 → 协作落地 → 验证反馈 → 复盘
```

重点追问：

- 创意解决了什么问题，而不只是“有趣”。
- 用户本人产出了文案、规则、关卡、原型、执行方案还是数据复盘。
- 哪些方案因成本、周期、技术或品牌限制被放弃。
- 如何提前验证理解成本、参与意愿和执行可行性。
- 最终效果与原始目标是否一致，有哪些非预期反馈。

## 场景题

- 活动报名高但到场低：分析承诺成本、提醒、时间地点、权益和报名质量。
- 游戏关卡流失高：区分难度、教学、目标感、反馈、性能和人群问题。
- 创意被认为不可落地：保留核心体验，拆最小版本并明确资源替代方案。
- 多方意见冲突：回到共同目标和验证证据，明确决策人和取舍原则。
- 内容热度高但品牌负面增加：检查表达与品牌定位、人群和风险边界。

## 答案框架

策划项目题：

```text
目标与受众 → 洞察 → 核心创意及理由 → 我的具体产出 → 机制与执行 → 验证反馈 → 取舍和复盘
```

策划场景题：

```text
澄清目标/受众/约束 → 定义核心体验 → 发散并筛选 → 拆机制流程 → 最小验证 → 资源排期 → 指标与风险预案
```

作品或项目不存在的数据不应补写，可描述将如何测试和验证。

## 正反例

正例：

> 目标是让新玩家在十分钟内理解合作机制。我没有先增加玩法，而是先画出教学流程，用纸面原型测试三组玩家；根据卡点删去一条支线，并用首次任务完成率和口头复述验证理解。

反例：

> 我脑洞比较大，设计了很多创新玩法，大家都觉得很有意思。

反例的问题：缺少目标、用户、个人产出、落地约束、验证方法和结果。

## 风险边界

- 不将创意数量等同于策划质量，不忽略落地、体验和验证。
- 不虚构作品数据、用户反馈、上线状态或个人主导程度。
- 不把团队产出、成熟 IP 资产或外部供应商成果归为个人成果。
- 涉及抽奖、付费、未成年人、内容表达时关注公平、合规和价值观风险。
- 不为追求传播制造误导、冒犯或不可控现场风险。
- 方法论只用于兜底，不覆盖用户事实和具体策划门类的专业规则。
