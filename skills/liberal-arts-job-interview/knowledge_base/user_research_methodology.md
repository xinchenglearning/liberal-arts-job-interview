# 用户研究校招方法论

## 使用原则

本文件仅作为用户研究岗位的出题与答题兜底，不覆盖用户提供的研究目标、样本、原始材料、分析结论、个人职责和项目影响。用户事实优先；缺失信息必须标记 `【待补充】`，不得用通用洞察替代真实研究发现。

## 核心目标

用户研究的核心是以适当方法获取可靠证据，解释用户的需求、行为和体验，并将发现转化为可执行的产品或业务决策。

- 将模糊业务问题转化为可研究问题。
- 选择适配目标、阶段和资源的方法。
- 控制样本、提问、分析与解释偏差。
- 区分用户表达、实际行为和研究者推断。
- 推动洞察进入决策，并追踪后续验证。

## 业务链路

```text
业务背景 → 决策问题 → 研究问题 → 方法设计 → 招募与样本 → 执行采集 → 整理分析 → 洞察与建议 → 沟通推动 → 后续验证
```

研究类型需匹配阶段：

- 探索性研究：理解需求、动机、场景和机会。
- 评估性研究：验证概念、原型、可用性和体验问题。
- 量化研究：估计规模、分布、关联和差异。
- 持续研究：跟踪满意度、用户声音和长期变化。

## 能力模型

| 能力 | 校招考察重点 |
|---|---|
| 问题定义 | 能否区分业务问题、决策问题和研究问题 |
| 方法选择 | 能否解释定性、定量及混合方法的适用边界 |
| 研究设计 | 能否控制样本、题序、提问和任务偏差 |
| 访谈观察 | 能否追问事实、场景和行为，避免诱导 |
| 数据分析 | 能否编码归纳、交叉验证并识别反例 |
| 洞察提炼 | 能否从现象形成有证据、有边界的解释 |
| 沟通推动 | 能否把发现连接到产品决策和优先级 |
| 伦理意识 | 能否保护知情同意、隐私和敏感群体 |

## 指标

- 研究质量：招募达成率、样本结构、有效样本率、数据完整性。
- 执行效率：招募周期、完成周期、单样本成本、按期交付率。
- 定量质量：回收率、完成率、无效问卷率、信度、置信区间。
- 可用性：任务成功率、完成时长、错误率、严重问题数、SUS 等量表。
- 洞察影响：建议采纳率、决策支持数、问题关闭率、后续验证结果。
- 护栏指标：隐私事件、诱导性、样本失衡、过度外推、研究疲劳。

不能以“访谈人数多”直接证明结论可靠；指标需结合研究目标和方法限制解释。

## 项目深挖

```text
决策背景 → 研究问题 → 方法与样本 → 个人职责 → 执行细节 → 分析证据 → 洞察边界 → 建议采纳 → 后续验证与复盘
```

重点追问：

- 为什么该问题适合研究，结论将支持什么决策。
- 样本如何定义和招募，遗漏了哪些群体。
- 访谈提纲或问卷如何避免诱导、双重问题和假设性偏差。
- 洞察由哪些原始证据支持，是否存在相反案例。
- 用户本人负责设计、执行、分析、汇报还是推动落地。
- 研究结论如何影响决策，未被采纳的原因是什么。

## 场景题

- 业务方要求访谈五人证明方案可行：澄清决策目标，说明定性不能估计比例，并补充行为或量化验证。
- 用户说喜欢但实际不用：对比表达、行为、场景和使用成本，设计任务观察。
- 时间只剩一周：缩小问题范围，优先高风险假设，采用快速招募和滚动同步。
- 访谈与数据冲突：检查口径、样本、时间和场景差异，形成可验证的新假设。
- 敏感人群研究：加强知情同意、匿名化、退出权和最小必要数据原则。

## 答案框架

研究项目题：

```text
业务决策 → 研究问题 → 方法与样本依据 → 我的具体动作 → 分析与交叉验证 → 洞察和边界 → 业务影响 → 复盘
```

研究场景题：

```text
澄清决策 → 定义研究问题 → 选择方法 → 设计样本与材料 → 控制偏差 → 分析计划 → 输出与推动 → 伦理和局限
```

答案必须区分观察事实、受访者表达、研究者解释和待验证假设。

## 正反例

正例：

> 业务方想判断新流程是否难用，我把问题转为三个关键任务的完成情况。招募覆盖新老用户，先做任务观察再追问原因；报告中区分高频障碍和个别偏好，并说明小样本不能估计总体比例。

反例：

> 我访谈了十个用户，发现大家都喜欢这个功能，所以建议尽快上线。

反例的问题：样本、提问方式、行为证据、结论边界和决策风险均不清楚。

## 风险边界

- 不虚构受访者原话、样本量、研究结论、采纳结果或个人职责。
- 不把小样本定性发现外推为总体比例或普遍规律。
- 不使用诱导提问、选择性引用或只保留支持预设的证据。
- 不收集超出研究目的的个人信息，敏感数据需最小化、匿名化和授权。
- AI 辅助转写、编码或总结时需人工复核，并防止隐私泄露和结论幻觉。
- 方法论仅用于兜底结构，不覆盖用户事实、研究伦理要求和组织数据规范。
